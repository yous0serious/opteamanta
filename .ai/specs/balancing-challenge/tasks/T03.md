# T03: Starker Bot + `npm run balance`

**Phase:** 1 · **Depends on:** T02 · **Covers:** AC-3 bis AC-7 (Messwerkzeug) · **Who:** hannibal

## Goal

Ein reproduzierbares Messwerkzeug zeigt, wie schwer das Spiel für zwei Bot-Strategien ist.

## Files

- New: `tools/bot-strong.ts`, `tools/balance.ts`
- Change: `tools/bot.ts` (Option `mode`, `balance`), `package.json` (Skript `balance`)

## Interfaces

```ts
playBot(opts: { seed; maxWave; mode?: GameMode; mapId?: MapId; balance?: BalanceConfig }): Game        // Referenz (Strategie unverändert)
playStrongBot(opts: { seed; maxWave; mode?; mapId?; balance? }): Game
```
`npm run balance [-- --json]` → Tabelle pro Bot/Modus: Läufe, Median Welle, Min/Max, Siegquote, „keine Moral in W1–5“-Quote,
maximale Tickzahl; dazu Prüfzeit (`runReplay`) des längsten Challenge-Laufs. Läufe: Seeds 1–5 × 4 Karten.

## Pseudo code (starker Bot)

- Zellen nach Pfadabdeckung bewerten: Anzahl Pfadpunkte (alle 10 px entlang des Pfads) in Reichweite des Turmtyps.
- Kaufreihenfolge: 1 Dualo, dann Entwickler; ab Welle 5 PPL zentral zwischen den Entwicklern; Analyst an Kurven;
  Scrum Master vor dem Pfadende; Upgrades bevorzugt Entwickler/PPL mit höchster Abdeckung.
- Vor PIP-Wellen (w ≡ 1 mod 5) Geld für Upgrades priorisieren.

## Verify

`npm run balance` gibt beide Tabellen aus, Laufzeit < 5 min.
