## Testfälle

1. Seite lädt, `canvas` sichtbar, `#money` = `200`, `#lives` = `100`; keine `console.error`/`pageerror` im ganzen Test.
2. Taste `3` → Button `.tw[data-t=dev]` hat Klasse `sel`; Klick auf eine freie Zelle (mit `?seed=7&map=waterfall`: Zelle (10,4),
   Pixel-Mitte 420/180 relativ zur 960×600-Fläche, auf die skalierte Canvas-Größe umrechnen) → `#money` = `80`.
3. Klick auf den platzierten Turm → `#info` enthält „Entwickler“; Taste `u` → Upgrade kostet 96 und wird bei 80 SP
   abgelehnt, `#money` bleibt `80`. Taste `s` → `#money` = `152` (80 + round(120·0.6)).
4. `?seed=7&map=waterfall&speed=10`: 2 Türme setzen, Leertaste 3×, jeweils warten bis `#big` wieder „STARTEN“ enthält (Timeout 60 s);
   `#wave` enthält „Sprint 2“ oder später.
5. Replay: `await page.evaluate(() => window.__bd.game.toReplay())` (mit `?debug=1`) → in Node mit `runReplay` aus `src/sim` prüfen → `matches === true`.
6. Game Over: `?seed=1&speed=10` ohne Türme, Leertaste wiederholt bis Canvas-Overlay/`#big` „NEU AUFSETZEN“ zeigt (Timeout 120 s); `#replay` sichtbar.
7. ESC und Rechtsklick heben die Auswahl auf (`.tw.sel` existiert nicht mehr); `#spd` zyklisch `x1→x2→x3→x1`; `#mute` wechselt Text.
